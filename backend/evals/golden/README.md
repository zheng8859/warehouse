# golden/ — Golden 数据集

事实来源：`20-评测体系设计`（已发布）；基线数值见 `../baseline.json`。

本目录存放**固定的评测输入样本**（场景 ID + 输入 + 期望输出），供 L1/L2/L3 三层 Evals
反复回放。Golden 样本是「劣化对比」的锚点：改代码后重放，输出偏离期望即判定劣化。

## 当前状态

**空目录** —— 数据集由阶段六（文档 `30-Evals评测体系`）建立。现在留空是刻意的：
没有真实样本时硬造样本，会让基线失去意义，比空着更糟。

## 建立时要遵守的约束

- **场景编号**沿用 `20` 号的定义，不要自拟：
  - `SC-001~006` 评分正确性（6 因子）
  - `CL-001~006` 作业闭环一致性（三类作业 + 台账 + 后验）
  - `AC-001~005` 分配合规（预留池 / 非 A 类 / 降级链）
  - `TR-001~005` 集中度趋势
- **样本来自真实数据**：用 `GTJ10036` 的历史导出切片，不要手写理想化数据。
- **每个样本带期望输出**，且期望输出必须可由设计文档推导（口径写在样本注释里）。
- **样本只增不改**：期望值要变，等于口径变了 —— 那是 `18` 号要版本化的事，不是改样本。
- 涉及真实物料/客户信息时**先脱敏**再入库（本目录进 Git）。

## 不做

`20` 号明确**不做 A/B 测试** —— 单厂 `GTJ10036` 只有一个活跃队列，无法拆流量对照。
试点验证用**前后对比**（预热 1 周 / 试运行 2 周 / 稳定 1 周），基线见 `../baseline.json`。
