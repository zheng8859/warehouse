# data-import Specification

## Purpose

定义数据衔接层「本层」的行为契约：三类作业文件（PO / DO / 库存快照）经数据时点标注、格式识别、字段映射、四层校验后建立基准（PO→入库队列、DO→出库任务、快照→cap 基线 + 库存分布），保证下游评分、批量分配与后验基于干净且时点明确的基准。

## Requirements

### Requirement: 数据时点标注与导入即基准

系统必须要求操作员在导入前标注数据时点（必填，默认当天），时点缺失或晚于当天即阻断导入；导入成功后，该时点快照成为后续评分、批量分配、顺路取派生与后验比对的唯一基准，后续变化只由台账事务增量产生。系统不得在时点缺失时静默兜底为当天。

#### Scenario: 时点缺失阻断
- **GIVEN** 操作员进入数据导入页但未标注数据时点
- **WHEN** 发起校验或执行导入
- **THEN** 系统阻断并提示「数据时点为必填」，不进入解析，不产生任何基准

#### Scenario: 未来时点阻断
- **GIVEN** 操作员标注的数据时点晚于当天
- **WHEN** 发起校验
- **THEN** 系统判定时点非法并阻断，不建立基准

#### Scenario: 导入成功即基准
- **GIVEN** 一次快照导入成功并建立基线，标注时点为 T
- **WHEN** 下游评分与后验取数
- **THEN** 均以 T 时点快照为唯一基准，不使用其他时点数据

### Requirement: 文件解析与字段映射

系统必须支持生产订单（PO）、交货单（DO）、库存快照（INV）三类文件分别上传，识别 xlsx / csv 格式并自动探测 UTF-8 / UTF-8-BOM / GBK 编码；无法识别格式或编码即阻断并提示。系统必须按 GTJ10036 单厂内置映射匹配模板列（别名、去首尾空格、全半角归一、大小写不敏感），字段命中率须 100%，未命中即阻断（防错位，不得静默忽略错列，严禁按列序号硬取字段）。

#### Scenario: 格式或编码不可识别阻断
- **GIVEN** 上传一个非 xlsx / csv 或编码无法探测的文件
- **WHEN** 发起解析
- **THEN** 系统阻断并提示「文件格式不支持或已损坏」/「请以 UTF-8 或 GBK 重新保存」，不猜测编码

#### Scenario: 字段未 100% 命中阻断
- **GIVEN** 上传的库存快照缺少模板必填列（如库位号列被改名且无法别名匹配）
- **WHEN** 发起字段映射
- **THEN** 系统阻断，回执显示「字段命中 n/m」并列出缺失列，不按列序号硬取

#### Scenario: 库位号按文本读取
- **GIVEN** 源文件中库位号写作 `010104`
- **WHEN** 解析并落库
- **THEN** 存储为字符串 `010104`（不丢前导 0），巷道取前 2 位 `01`

### Requirement: 四层校验与阻断

系统必须在执行导入前完成四层校验：结构（可解析、非空）、字段（模板要求列全部命中）、时点（已标注且不晚于当天）、业务（数量 > 0、库位号可切片出巷道、批号非空、仓库号与单厂一致、状态取值在枚举内）。任一阻断级异常即阻断导入（不得带病入库），回执可展开到「文件 + 列 + 行 + 原因」级明细。选填字段缺失不得阻断，但须降级处理并在回执标注（降级不静默）。

#### Scenario: 业务口径异常阻断并展开行级明细
- **GIVEN** 库存快照中存在数量 ≤ 0 或批号为空的记录
- **WHEN** 发起口径校验
- **THEN** 系统计入口径异常并阻断导入，回执可展开到行级明细（文件 + 列 + 行 + 原因）

#### Scenario: 选填字段缺失降级不阻断
- **GIVEN** 库存快照缺少「品名」选填列
- **WHEN** 发起校验
- **THEN** 系统不阻断，回执标注该选填列缺失（相关展示降级），其余必填列命中通过

### Requirement: 执行导入与建立基准

系统必须在用户点击「执行导入」后，将校验通过的三类文件分流：PO 写入入库待推荐队列（`JobOrder` 置 `PENDING`）、DO 写入出库拣配任务（`JobOrder` 置 `PENDING`）、INV 建立 cap 基线并生成既有库位 / 批次分布（`InventoryItem`）。写入或分流任一失败即回滚该批（不产生半成品基准）。系统不得在未校验通过或未执行导入时提前分流。

#### Scenario: 三类文件分流到各自去向
- **GIVEN** 三类文件均校验通过且操作员点击「执行导入」
- **WHEN** 导入完成
- **THEN** PO 进入库待推荐队列、DO 进出库拣配任务（均 `PENDING`）、快照建立 cap 基线 + 库存分布

#### Scenario: 写入失败回滚该批
- **GIVEN** 执行导入过程中某类文件写入异常
- **WHEN** 事务提交失败
- **THEN** 该批整体回滚，不产生任何半成品队列 / 任务 / 基线，状态置 `FAILED` 可修正后重导

### Requirement: cap 基线全量重算

系统必须在快照导入成功（`IMPORTED → BASELINE`）时按巷道全量重算 cap（非增量累加）：以库位号 `[:2]` 切片聚合，计算 `cap_physical`（巷道物理总格数，主数据到位前以快照库位去重格数近似）、`cap_total`（`cap_physical` − 已占格数）、`cap_reserved`（`cap_physical` × 40% 固定预留带，仅近站台巷道）、`cap_usable`（`max(cap_total − cap_reserved, 0)`），生成新 `Snapshot` 版本、旧版本归档不删除。重算失败即回滚该批并提示重导。

#### Scenario: 快照导入触发全量重算与新版本归档
- **GIVEN** 已存在旧基线 `snapshot_id = 1`，导入新快照成功
- **WHEN** 建立基准
- **THEN** 按巷道全量重算 cap 生成 `snapshot_id = 2`，旧基线 1 仍完整可读（归档不删除）

#### Scenario: 重算异常回滚并提示重导
- **GIVEN** 快照导入后 cap 全量重算发生异常
- **WHEN** 建立基准失败
- **THEN** 该批回滚，不生成新基线，提示「重算异常，请修正后重导」

### Requirement: 重复导入判定与幂等

系统必须以「数据时点 + 文件校验和」判定重复导入：同一时点且文件校验和相同即判定重复，提示用户选择「跳过」或「覆盖重算」，不得静默覆盖；覆盖时重新建立新基线版本、旧版归档。已 `BASELINE` 的会话再次提交须幂等返回既有基线，不得重复建立。

#### Scenario: 同时点同校验和判定重复
- **GIVEN** 已导入某时点快照，再次上传同时点且校验和相同的文件
- **WHEN** 发起校验
- **THEN** 系统提示「该时点快照已导入」，由用户确认跳过或覆盖重算，不静默覆盖

#### Scenario: 已建基准会话幂等返回
- **GIVEN** 某 `ImportSession` 已 `BASELINE`
- **WHEN** 重复提交该会话的执行导入
- **THEN** 系统直接返回既有基线，不重复建立，不产生第二条基线

### Requirement: 部分文件失败隔离

三类文件必须独立校验与导入，某类失败不得影响其他类；但库存快照失败 = 无 cap 基线，容量与顺路取相关环节受限并在回执明确提示（成功 N 类 / 失败 M 类），不得静默吞掉失败。PO / DO 失败仅影响各自队列 / 任务，不阻断其余文件。

#### Scenario: 快照失败不阻断 PO/DO 载入但容量受限
- **GIVEN** PO / DO 校验通过、库存快照校验失败
- **WHEN** 执行导入
- **THEN** PO / DO 正常载入各自队列 / 任务，但无 cap 基线，容量与顺路取相关环节受限并在回执提示；回执明确「成功 2 类 / 失败 1 类」

### Requirement: 数据导入页数据层

数据导入页 p2 必须接入后端导入 API：数据时点卡、三类文件上传、校验结果表与「开始校验 / 执行导入」两步交互均由真实接口驱动，用空 / 加载 / 成功 / 异常四态渲染，替换硬编码「通过」结果。校验失败时状态列显示失败并支持展开异常明细，修正文件后可重新校验（`FAILED → DRAFT`）。

#### Scenario: 校验结果表由接口驱动
- **GIVEN** 操作员上传文件并点击「开始校验」
- **WHEN** 后端返回校验回执
- **THEN** 结果表按真实回执渲染文件 / 解析条数 / 字段命中 / 口径异常 / 状态，不再显示硬编码数值

#### Scenario: 校验失败可展开明细并重新校验
- **GIVEN** 某类文件校验失败，回执含行级异常明细
- **WHEN** 操作员展开明细并修正文件后重新校验
- **THEN** 会话由 `FAILED` 回到 `DRAFT` 重新校验，失败状态可恢复为通过

### Requirement: 成品清单 ABC 统计导入

系统必须提供成品清单 ABC 统计导入（脚本通道，非页面交互）：读取 BI 看板需求的「成品清单」历史出入库流水，按料号聚合出库量，按累计出库量占比分档（A≤70% / B≤90% / C 其余），并将结果 upsert 到 `Material.abc_class`；料号不存在于主数据时记告警并跳过，不阻断。该导入不建立基线（不产生 `Snapshot`、不进入 `ImportSession` 状态机）、不产生队列 / 任务，失败不阻断三类作业文件导入；数据导入页 p2 不得展示或接线该导入（无上传位、无结果卡）。

#### Scenario: 按出库量累计占比分档
- **GIVEN** 成品清单存在多个料号的出库流水
- **WHEN** 运行 ABC 统计导入
- **THEN** 按料号出库量降序累计，累计占比 ≤70% 归 `A`、≤90% 归 `B`、其余归 `C`，并写入对应 `Material.abc_class`

#### Scenario: 不建基线不进状态机不产生任务
- **GIVEN** 运行 ABC 统计导入
- **WHEN** 导入完成
- **THEN** 不产生 `Snapshot`、不产生 `ImportSession`、不产生 `JobOrder`，仅更新 `Material.abc_class`

#### Scenario: 料号不存在记告警跳过不阻断
- **GIVEN** 成品清单含某料号，而 `Material` 主数据中无该料号
- **WHEN** 运行 ABC 统计导入
- **THEN** 该料号记告警并跳过，不影响其余料号分档，也不影响三类作业文件导入

#### Scenario: 不进数据导入页
- **GIVEN** 操作员打开数据导入页 p2
- **WHEN** 观察可用的上传位
- **THEN** 仅有数据时点卡与 PO / DO / INV 三类上传位，无成品清单 / ABC 上传位或结果卡
