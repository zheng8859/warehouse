# evals Specification

## Purpose

成品库位智能推荐的评测执行框架：以 60 个可溯源 Golden 场景驱动三层评测（L1 单元 ≥95% / L2 集成 ≥90% / L3 质量达验收口径），用基线对比与劣化检测守护代码质量，并为 v1.0 试点提供 Go/No-Go 闸门。

## Requirements

### Requirement: Golden 数据集三层组织与可溯源

系统必须维护 60 个命名 Golden 场景（`golden_001`~`golden_060`），按三层组织——基线层 24、边界层 20、回归层 16——覆盖 13 个评测维度；每个场景必须携带唯一 `golden_NNN` 标识、所属层、维度、触发输入、期望输出、容差与断言类型，且可溯源到 20号 的 SC/CL/AC/TR 编号。

#### Scenario: 数据集规模与分层
- **WHEN** 评测框架加载 Golden 数据集
- **THEN** 数据集包含 60 个场景，且基线层 24、边界层 20、回归层 16 的计数分别成立

#### Scenario: 场景可溯源
- **WHEN** 查看任一 `golden_NNN` 场景
- **THEN** 该场景携带可定位到 20号 编号（SC/CL/AC/TR）与维度名的溯源注释，期望输出可由 14/15/18 号公式推导

### Requirement: L1 单元层通过线 ≥95% 且评分确定性 100%

系统必须运行 L1 单元层评测（基线层 24 场景及边界层可断言的纯函数），通过率 ≥95%；其中评分正确性维度要求同输入同输出，确定性必须为 100%——任一非确定（引入随机/时间源/无序遍历）即判该场景失败。

#### Scenario: L1 通过率达标
- **WHEN** 运行 L1 层评测
- **THEN** 系统输出 L1 通过率，且通过率 ≥95% 时该层判定通过

#### Scenario: 评分确定性 100%
- **WHEN** 对同一评分输入重复运行两次
- **THEN** 两次输出完全一致；任一非确定输出即判 L1 失败

### Requirement: L2 集成层通过线 ≥90%

系统必须运行 L2 集成层评测（API 端点行为：导入 8 步、JobOrder 状态机、Ledger 写入、KPI 聚合、权限守卫），通过率 ≥90%，且必须覆盖 401/422/404 错误守卫断言。

#### Scenario: L2 通过率达标
- **WHEN** 运行 L2 层评测
- **THEN** 系统输出 L2 通过率，且通过率 ≥90% 时该层判定通过

#### Scenario: 错误守卫覆盖
- **WHEN** L2 场景对受保护端点发送无凭据/非法/不存在的请求
- **THEN** 系统分别断言 401/422/404 响应，未覆盖者不计入通过

### Requirement: L3 质量层达 18 号验收口径（趋势判定）

系统必须运行 L3 质量层评测，按 18号 验收口径判定业务指标——同物料跨巷道 ≤5、同批跨巷道 ≤3、拣货量加权集中度 80% 落 ≤N（N=5）达成率 ≥70%、采纳率 ≥60%——L3 为趋势判定，不设简单百分比门槛，其放行以 20号 §7.5 Go/No-Go 闸门为准。

#### Scenario: 同物料与同批跨巷道口径
- **WHEN** L3 对合成台账/快照运行跨巷道指标计算
- **THEN** 系统断言同物料跨巷道 ≤5 且同批跨巷道 ≤3，超出者标记不达标

#### Scenario: 加权集中度达成率闸门
- **WHEN** L3 统计试点期末加权集中度达成率
- **THEN** 系统判定达成率 ≥70% 且趋势向好为达标，任一护栏失败即回滚（功能开关式，不删历史台账）

### Requirement: 评测运行器的分层与维度过滤

系统必须提供评测运行器（`run_evals`），支持 `--tier`（l1/l2/l3/all）分层运行、`--dimension` 按 13 维度过滤、`--run-slow` 纳入慢测，并输出各层通过率与退出码。

#### Scenario: 按层运行
- **WHEN** 以 `--tier l1`（或 l2/l3/all）运行评测
- **THEN** 系统只运行对应层的评测并输出该层通过率

#### Scenario: 按维度过滤
- **WHEN** 以 `--dimension <维度名>` 运行评测
- **THEN** 系统只运行命中该维度的场景，用于定位缺陷

### Requirement: 基线对比与劣化检测

系统必须在 `--compare baseline.json` 时对比当前通过率与基线：劣化 ≤3% 记为正常波动继续；劣化 3–5% 告警（non-blocking）；劣化 >5% 阻断合并（对应 revert/修复决策）。

#### Scenario: 劣化 ≤3% 正常波动
- **WHEN** 对比基线且劣化幅度 ≤3%
- **THEN** 系统记录为正常波动并以成功退出

#### Scenario: 劣化 3–5% 告警
- **WHEN** 对比基线且劣化幅度在 3% 至 5% 之间
- **THEN** 系统产出告警（non-blocking）且不阻断合并

#### Scenario: 劣化 >5% 阻断
- **WHEN** 对比基线且劣化幅度 >5%
- **THEN** 系统以失败退出码阻断合并，并提示定位 bad commit

### Requirement: P0 护栏立即阻断

系统必须在以下任一 P0 护栏被突破时立即阻断并触发回滚：台账完整性 100% 被破坏、决策可追溯 100% 被破坏、核心链路出域事件 >0；回滚为功能开关式，不得删除历史台账。

#### Scenario: 台账完整性被突破
- **WHEN** 评测发现台账未写/写错巷道或决策链路断裂
- **THEN** 系统立即阻断，不得放行

#### Scenario: 出域事件大于零
- **WHEN** 评测检测到核心链路发生出域请求（未脱敏或核心链路出域）
- **THEN** 系统立即阻断并关停相关链路，出域事件计数不得为 0 之外的值

### Requirement: 基线版本随代码 tag 且基线下调不允许

系统必须支持 `--save-baseline` 将当前通过率保存为基线；首个回放基线对应代码版本 v0.6.0，后续仅在「确认改善真实 + 代码升级」时更新基线并同步新 tag；基线下调不允许。

#### Scenario: 建立首个基线
- **WHEN** 在 v0.6.0 代码上执行 `--save-baseline`
- **THEN** 系统保存基线并与 v0.6.0 tag 对应

#### Scenario: 基线下调被拒绝
- **WHEN** 尝试保存一个低于现有基线的通过率
- **THEN** 系统拒绝下调基线，长期不达标须查根因而非降标准

### Requirement: 冷路径 LLM 建议可用性观测非闸门

系统必须把冷路径 LLM 四类能力（KPI 解读/偏离归因/权重调优/移库方案）仅作「建议可用性」观测——统计是否覆盖主因、是否误导、人工采纳率——不计入任何通过率门槛。

#### Scenario: 冷路径观测不进门槛
- **WHEN** 冷路径 LLM 输出非确定或无标准答案
- **THEN** 系统仅记录观测项，不得将其计入 L3 通过率门槛

### Requirement: CI 门禁

系统必须通过 pre-push 评测钩子与 CI 工作流执行门禁：L1 通过率 <95% 阻断、L2 通过率 <90% 阻断、L2/L3 劣化 >5% 阻断、P0 护栏被突破立即阻断。

#### Scenario: L1 低于阈值阻断
- **WHEN** L1 通过率低于 95%
- **THEN** 门禁阻断合并，不得放行

#### Scenario: 劣化大于 5% 阻断
- **WHEN** L2/L3 对比基线劣化大于 5%
- **THEN** 门禁阻断合并
