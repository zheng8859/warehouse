## Why

8 页 HTML 原型已完成（`backend/frontend/`），其共享 `assets/styles.css`（`:root` 设计令牌 + 语义组件）与 `assets/app.js`（导航 `data-tab` + 登录壳 + 交互钩子）**已随原型实现了基础层主体**。但三件事仍欠着：

1. **令牌色值与权威值大面积偏离**——`styles.css` 的 12 个色令牌里 11 个与 `21` §3.3（=`24` §3.1 原样内联）不一致（`--blue` 现状 `#5b8def` vs 规范 `#2f6fed` 等），且 `24` §6.3 明令「生成时所有色值取自 21 号 `:root`，禁止硬编码冲突色值」。这正是 CLAUDE.md §十 记的「令牌取值与 21/24 规范值不一致…留待阶段七」。
2. **壳级缺口**：角色菜单可见性（`13` §3.1 前端过滤）未接、四态占位（空/加载/成功/异常，`21` §7.11）未系统化、`.node` 流程状态卡（entry/exec/ledger 三态，`21` §7.2/§7.8）缺失。

本变更按 `31` 号文档的「基线核对 + 缺口补齐」定位：**只核对已实现项、只补壳级缺口、只修偏差**——不重写令牌/组件主体/壳/对话台壳，不碰 p1~p8 页面正文，不调业务 API、不调引擎。

## What Changes

- **令牌纠偏（偏差修正，以 21/24 为权威）**：`styles.css` `:root` 的 11 个色值对齐 `21` §3.3；三处派生冲突色（`.pill.ok` 底、`.btab` 表头底、`.dock` 阴影的旧蓝 `rgba`）与 L2 冷路径 chip 描边（`#a99bc8` → 紫灰 `#5b4b96`，`24` §6.3）、`.reason` 因子列宽（`72px` → `64px`，`22` §三）一并对齐
- **角色菜单可见性**：`app.js` 落 `13` §3.1 菜单矩阵 + 按 `sessionStorage` 角色过滤 `nav`；登录壳加一个角色下拉（4 角色），登录后写入 `sessionStorage`
- **四态占位系统化**：`styles.css` 落空/加载/成功/异常四态全局样式 + `app.js` 落 `setState()` 触发钩子（`21` §7.11）
- **`.node` 流程状态卡**：`styles.css` 落 `.node` entry（蓝）/ exec（绿）/ ledger（琥珀）三态 + `.flow` 管线容器（`21` §7.2/§7.8）
- **组件冒烟**：`backend/tests/frontend/` 落静态断言（令牌值、菜单矩阵、四态、`.node`），无浏览器

## 非目标

- **不重写已实现项**：令牌变量名、组件主体、应用壳导航/登录、对话台壳（`.dock/.bar/.qs/.bub/.confirm`）已实现，只核对、不改结构（令牌只改色值不增删变量）
- **不碰 p1~p8 页面正文**：页面内容与业务交互、各页状态接入四态、`.node` 在作业页的实际可视化，归 `28`（整合层）
- **不调业务 API / 引擎**：本层零后端调用；对话台 L2 的脱敏 LLM 逻辑归 `29`（冷路径），`.qs.l2` 仍仅入口按钮
- **不做后端 RBAC 强制**：菜单过滤是 v1 前端近似（`13` §三/§六），后端端点级 RBAC 仍路线图
- **不做页面正文级的访问拦截**：直接 URL 访问某页不由本层拦截（那是 28/路由的职责），本层只过滤导航渲染

## Capabilities

### New Capabilities

- `frontend-foundation`: 设计令牌权威值一致（21 §3.3=24 §3.1）、角色菜单可见性（13 §3.1 前端过滤）、四态占位（21 §7.11）、流程状态卡 `.node` 三态（21 §7.2/§7.8）

### Modified Capabilities

（无——本变更不触碰既有 `auth` / `data-model` / `permission` / `recommendation-engine` 规格。角色菜单可见性是 `13` §3.1 的**前端过滤**，与 `permission` 规格的 `13` §2.2 后端矩阵、`配置子模块受限` 是两层：后者约束「谁能改」，本变更约束「导航渲染出什么」。）
