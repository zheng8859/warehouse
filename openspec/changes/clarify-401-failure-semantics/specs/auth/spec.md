## MODIFIED Requirements

### Requirement: 登录端点与失败语义

`/api/auth/login` 必须免认证可访问。登录失败必须一律返回 401 —— 用户名不存在、密码错误、账号非激活三种情形必须返回**同一响应体**，不得透露账号是否存在。

受保护端点在凭据缺失、无效、过期或签名错误时也必须一律返回 401，不得返回 404（不泄露路径是否存在）。**但 401 响应体必须区分失败原因**（凭据过期 / 签名不匹配 / 载荷不合法等）—— 这条与登录端点相反，且是有意的：登录端点的响应面向未认证的任何人，而凭据校验的逐因文案只在**签名校验通过之后**才可达，够得着的人要么是合法签发方（逐因文案正是给他的诊断信息），要么已持密钥。

#### Scenario: 登录端点免认证
- **GIVEN** 未携带任何凭据
- **WHEN** 以合法用户名与密码请求 `/api/auth/login`
- **THEN** 返回 200 与凭据

#### Scenario: 失败原因不区分
- **GIVEN** 一个不存在的用户名，与一个存在但密码错误的账号
- **WHEN** 分别提交登录
- **THEN** 两次响应均为 401 且响应体一致，不泄露账号是否存在

#### Scenario: 凭据校验的 401 保留失败原因
- **GIVEN** 一份已过期的凭据，与一份签名被篡改的凭据
- **WHEN** 分别携带它们请求受保护端点
- **THEN** 两次均为 401，且两次的 `message` 不相同 —— 前者指出已过期，后者指出签名不匹配
